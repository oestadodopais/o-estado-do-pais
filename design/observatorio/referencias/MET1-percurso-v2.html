How O Estado do País works

Everything that happens from the moment the daily watch starts until a piece of work goes live: every check, gate and read, which parts are scripts, which are AI models and which is a person. Seventeen steps in three parts.

      Models judge in five places; scripts do everything around them

      This map follows one piece of work from the morning watch to the live page. Every box is done by one of three kinds of actor: a script, which gives the same result every time; a model, which makes a judgment; or the funder, the one person in the loop. Judgment sits in five places: the watch, the mandate, the build, the cold read and the fixes.

      Details

      • The rule throughout: models write and judge, scripts do the rest. Where a model’s output is then checked by a script or by planted faults, the map draws the link in cobalt: the build is checked by the build and verification chains, the cold reader is tested by five planted faults, and each fix is checked again.
      • Dashed boxes are switched off or not yet built: the automatic watch of Parliament and the Diário da República and the daily re-check of every source (built, switched off), and the news feeds read by script and the upload of an already-checked build (planned).

      Every figure comes from a public body’s own publication

      Statistics offices, ministries, Parliament, the official journal and the press publish the documents. Who published each one is never typed by hand: a script measures the name in the hosted document itself, and the name must belong to a closed register of 58 publishing bodies.

      checks here1 register check on every receipt58 bodies in the register

      • Script reads the publisher’s name in the hosted source document: og:site_name on a web page, JSON-LD, the issuer of a PDF.
      • Script refuses any receipt whose «Publicado por» is not in the register or does not match the document’s domain, so a person can never appear as a publisher.
      • Model chooses which documents a piece of work needs, in the mandate. It does not decide who published them.

      Details

      • The person quoted and the publisher are different fields. In the health budget case (step 07), the minister’s words were published by RTP, so RTP is the publisher.
      • Rows calculated from other rows have no single publisher; they name the rows they come from (step 03).

      Found on 02.11.202626 receipts named the person quoted as the publisher. A newspaper article quoting someone, for example the Prime Minister, was credited to that person instead of the newspaper. All 26 were fixed on every page of the site and listed as corrections, and the register check now refuses the whole class. The same day, rule 15 was adopted: a defect a reader can see is fixed for its whole class, on every page, current and future, by a check with a planted fault that proves it bites. It is not fixed only on the page where it was found.

      One file per figure, and per quote

      Nothing reaches a page as a typed number. Each figure, and each quote, is a small file in the ledger with its value, unit, source, document, link, the date it was read and the exact words it came from. Pages cite the file’s id, and the build fills in the value.

      checks hereinside the 28 build stepssee step 12

      • Script the engine writes each row; the file itself says it is not edited by hand. Re-checks are written by the engine too.
      • Script every build refuses a digit on a page that has no row, and recomputes every calculated value; a result that differs fails the build.
      • Model the mandate picks the figures a page needs, by id. Values reach the sentences as fields filled in by a script, never typed.

      Details

      • 4 144 files, measured 03.11.2026. The one on the left is real: Évora’s resident population in 2025, from INE indicator 0012918.
      • 519 rows have no single source because they are calculated from other rows. Each names the rows it comes from and carries its formula.
      • A page cites a row by its id, as <Claim id="…" />. A number typed straight into a page fails the build.
      • The excerpt is copied word for word. What could not be confirmed at the source is never filled with a plausible value; the page says what is missing.
      • Re-checks are appended under verifications, never overwritten. Both re-checks of this row returned «igual» (unchanged).

      Every source document is kept, fingerprinted and measured

      Research starts by hosting the documents. A copy of each is kept with its SHA-256 fingerprint, so anyone can later prove the copy is the one that was read. The facts the work depends on are then measured on that copy by a script, before any model writes about them.

      checks herea fingerprint on every hosted documenta package refused if one is missingcounts, ranks, causes and dates measured first

      • Script hosts each source document with its SHA-256 fingerprint.
      • Script measures any count, rank, cause or date in a mandate on the hosted document, before the mandate is written.
      • Script refuses a cold-read package when a hosted document is missing.
      • Model a model prepares fact sheets. The director decides what they mean, and states a cause as interpretation until the source shows the mechanism.

      Details

      • A conclusion keeps the measure, the definition and the qualification of every number it uses.
      • Saying a document is silent on something requires a full search of it, recorded in the mandate.
      • The cold reader works from the same hosted copies, checked by fingerprint, so the writer and the reader read the same text.

      Published values are checked again against their source

      Sources revise their figures, so a published value can go stale. A script asks the source again and appends the answer to the row. A change is appended and listed, never written in silently.

      checks here91 lines re-read every weekdaily re-check: built, switched off

      • Script a weekly panel re-reads 91 lines against their sources.
      • Script, switched off the corredor diário, the daily re-check of every source at 06:10 UTC, is built but not running.

      Details

      • Every re-check is appended to its row, never overwritten. Totals so far: 4 102 «igual» (unchanged), 42 «diverge» (changed) and 5 «inacessível» (unreachable), across 2 636 rows.
      • The corredor diário is built to ask every source each morning and to download only what changed, using the publisher’s own «not modified» answer or a digital fingerprint, so a quiet day costs almost nothing.

      Each working session starts by reading the country

      Before anything is built, a model reads the news, what parties and politicians say, and new reference studies, and sorts what it finds into a short list. The director chooses the layer each item deserves: a panel item, an article or a study. Reading the news feeds by script, with the model only sorting, is planned and not yet built.

      • Model does the sweep at the start of each session: the news, the parties, the reference studies.
      • Script, planned reading the news feeds by script, so that the model only sorts, is not yet built.
      • Script runs specific watches when something is due, for example every two hours for the Évora 2027 European Capital of Culture pages.
      • Script, switched off the automatic daily watch of Parliament and the Diário da República is built but not running.
      • Model an inexpensive model is meant to do this daily, and one is on trial for it.
      • Model the director picks the layer for each item.

      Details

      • Each item on the list carries the claim and who made it, the numbers at stake, the primary sources, the layer it deserves and the estimated cost.
      • The sweep also collects public figures that quote one of the site’s measures with a different value, for a comparison note.
      • The session’s first block of content comes out of this list.

      A claim, set beside the document that measures it

      This is what the project is for. A claim goes next to the official document that measures the same thing. The page then explains what each side shows, what it leaves out, what it means for people, and who is right and why. It ends with a conclusion, a recommendation and an opinion signed as the director’s.

      checks hereevery number sealed5 planted faults in the cold read

      • Model the director writes the analysis: as it was said, what the sources say, the comparison, the conclusion, the recommendation and the director’s opinion.
      • Script prints each quote from its ledger row, in its declared form, with its publisher.
      • Script seals every number in the analysis like any other figure, and measures any count, rank, cause or date first.
      • Model another model family reads the page cold and answers one question: would the editor of a Portuguese daily print it as it is?

      Details

      • A person is named only beside something they said or did in public, with the document a tap away, next to what the sources say about the same measure, period and population. The numbers judge, without adjectives; when the sources show a claim is false, the page says so.
      • The director writes each sentence of the analysis with the source excerpt beside it, and a sentence may say only what the sealed rows and the source say.

      A real case, live on «O que se discute»The 2027 health budget. The minister said the health budget rises 3% once the PRR recovery money is set aside; RTP reported a cut of 1,5 per cent; the PCP said investment is cut by 33,7%. All three figures are in the same budget table (Quadro 5.37), each on a different line: spending without the PRR, total spending, and investment with the PRR. None of the three shows the lines together. Set the PRR aside and investment rises 22,2 %. All three quotes are declared as the speakers’ own words, and the minister’s «sobre» stays as RTP published it.

      Every quotation keeps its form, and every seal keeps its place

      Each quotation declares what it is: an assertion, the person’s own words, or a press report («relato»). Scripts hold each form to its rule, and check where every «fonte» seal sits on all 9 823 built pages.

      checks here2 script checks9 823 pages read

      • Script refuses a press report that does not name the report in the same sentence.
      • Script refuses a person’s own words framed as anything else.
      • Script reads the rendered text of all 9 823 pages: the seal sits after the whole measure, and two seals never sit side by side.
      • Model the director writes the sentence around each quotation in the mandate; the scripts check its form.

      Details

      • «79 milhões de euros ■ fonte» is right. «79 ■ fonte milhões» is refused: the seal must follow the whole measure, unit included.
      • Quotations and source texts are never drawn as number cards.

      One model decides, and writes the sentences

      The director decides what the site says, what gets built next and when it goes live. For each block of work it writes a mandate that includes the exact sentences readers will see.

      checks hereevery count, rank, cause and date measured by script first

      • Model the director is a top-tier model. The roles never change; which model holds each one today is listed on the site’s AI policy page, updated in the same change as the roles.
      • Script measures every count, rank, cause or date in the mandate on the hosted document, before the sentence is written.
      • Model the builder may object to a sentence; it is not printed until the director rewrites it.
      • Person the funder reads the finished work as a reader and says what was hard to read. Money, legal exposure and anything sent out in the project’s name stay with the funder.

      Details

      • The director reads the built sentences in both languages before the cold read starts.
      • Source identifiers (pages, tables, figures) reach the sentences as fields checked by a script, never typed by hand.

      Another model builds, alone and on a budget

      A builder model builds each block from the mandate, in its own copy of the code, under a fixed budget. Anything a script can do more exactly than a model is done by a script.

      checks here75 minutes per pass120 calls per passone build at a time

      • Model the builder works in its own copy of the code (a git worktree), so its work cannot disturb anyone else’s. A second model is the backup builder.
      • Script the launcher enforces each pass’s budget: 75 minutes and 120 calls.
      • Script a lock allows one build at a time on the machine.
      • Script sealing rows, composing pages, checking, capturing and landing are scripts, at zero model cost.

      Details

      • The rule: models write and judge, scripts do the rest. Models are used in five places only: the daily watch, the mandate, a short build, the cold read and a targeted fix.
      • The builder decides small ambiguities itself and notes them in its report.
      • Each block’s model cost is measured and committed with it (step 13).

      A different model family reads it cold, with five planted faults

      Before anything goes live, a model from a different family reads the change without having seen it built. It gets a package in which five faults were planted on purpose. If it misses one, its «all clear» means little.

      checks here5 planted faults per reada short read after every correction that changes a sentence, a number or a check

      • Script assembles the package (the mandate, the builder’s report, the diff, the changed files, the built pages and the hosted documents) and refuses it if a hosted document is missing.
      • Script plants five faults in the reader’s copy only, each recorded by its fingerprint. The reader is never told where.
      • Model whoever builds never verifies: the reader is always from a different model family than the builder, and can only read.
      • Model the fixes: Blocking and Major findings are fixed before release, and a short read follows every correction that changes a sentence, a number or a check. Minor ones go to the Friday clean-up.

      Details

      • A finding about a person, a false sentence or a cause stated as fact never lets a block land.
      • The reader also answers one question: would the editor of a Portuguese daily print this page as it is?
      • It is not a guarantee. The made-up 53 011 slipped past readers who had found every planted fault. That is why the build checks exist as well.

      Any red step stops everything

      Every build runs a chain of 28 steps, and the first failure stops it. The full verification runs 58 steps plus a type check. Nothing new is published until every step passes.

      checks here28 build steps58 verification steps1 type check

      • Script every step in both chains is a script: the same input gives the same result.
      • Script a defect a reader can see becomes a check for its whole class, with a planted fault that proves it bites (rule 15).

      Details

      • In the build, among others: every row is complete (ledger:check); the files every session reads first are true (check:registo); hosted studies are byte for byte the original, proved by SHA-256 (check:documentos); every digit on every page has a row (gate:html); a study’s text cannot change without a new edition (check:edicoes); no seal sits inside a measure or beside another seal (check:selos).
      • The full verification adds, among others, the publisher register (check:publicadores) and the quotation forms (check:forma-citacao).
      • A check that protects a number, a source or a person is never weakened. If it changes shape, a planted fault proves it still bites.

      This really happenedA made-up population for Évora, 53 011, appeared in a builder’s report, slipped past the cold readers and was copied into the file every session reads first. The website never showed it: its pages said 58 567. But no check read that file, so a new one was built (check:registo). It now refuses that number: wrong value, and no ledger id.

      Finished work lands in batches, and every block has a cost

      Finished blocks wait and land together, at most two batches a day. Each block’s model cost is measured and committed with it, against a target of fewer than 5 points per block. A block over budget stops and goes to the funder.

      checks herethe independent full check on the exact versionthe machine checksat most 2 batches a day

      • Script an independent check service must run the full check green on the exact version that lands. On 02 and 03.11.2026 it took 33 to 50 minutes.
      • Script then the machine checks run, and the version is merged into main and pushed.
      • Script measures each block’s model cost and commits it.
      • Person decides on any block over budget. On 03.11.2026 the funder approved two blocks, at 11 and 8 points, each time the director asked.

      Details

      • Nothing red reaches main. The merge only moves main forward to the exact version that passed.
      • The landing refuses a block without its cost, or over budget, unless the funder decides otherwise in writing.

      Published, then questioned live

      Once main moves, the publishing service rebuilds the site and publishes it, in about 33 minutes. A script then questions the live site to confirm that what is online is what was approved, and the captures go to the funder.

      checks hereverify:deploy on the live sitecaptures at 5 widths, in both languages

      • Script the publishing service rebuilds and publishes the pushed version.
      • Script verify:deploy asks the live site: is the version on air the one on main? Are the security headers there? Do the other addresses redirect? Does each language get its own «not found» page?
      • Script captures each finished block at five widths, from 390 to 1 600 px, in both languages.
      • Person the captures go to the funder, who reads them as a reader.

      Every value opens its own source

      On the page, each measured value carries a seal that opens its ledger row. Both languages come from one build: 9 823 pages in Portuguese and English.

      • Script one build makes both editions, Portuguese at / and English at /en/. The two languages must have the same set of texts, or the build fails.
      • Script checks the seal’s place in the rendered text of every page.

      Details

      • Beside every measured value sits a seal: a small square and the word «fonte». Tap it to open the row: the source, the document, the date it was read, the exact excerpt and every re-check.
      • The Évora page shows 58 567, the value in its row. The made-up 53 011 never reached it.

      A study keeps its first edition, and every change is dated in public

      Each study keeps its first edition untouched, identified by its fingerprint. Text that changes without a new version fails the build, and every change of text has a dated entry in the public corrections register.

      checks here1 build step: check:edicoes4 kinds of correction45 published

      • Script keeps each study’s first edition identified by its fingerprint, and fails the build when text changes without a new version.

      Details

      • Correção: a value, or a receipt field, was wrong when it was published.
      • Atualização: it was right, and what it measures changed.
      • Revisão de proveniência: the path to the source changed later. This is not an error.
      • Estudo corrigido: a study’s text was corrected, with both versions one tap away.
      • 45 corrections are published.
