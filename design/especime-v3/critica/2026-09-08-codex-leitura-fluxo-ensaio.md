## Blocking

1. **The scheduled trigger runs on days 5–14 of every month in every year, not only 5–14 September 2026.** In the five-field cron expression, the month field is `*`. The comments notice the missing year restriction but incorrectly assume September is encoded. If left enabled, the next unintended dispatches begin on 5 October 2026, not September 2027.

2. **The workflow neither enforces one dispatch per night nor confines manual dispatches to the intended dates, and it has already dispatched outside them.** `workflow_dispatch` is permanently available, and the job contains no date, prior-run, or event-type guard before the POST; a manual invocation or rerun can therefore issue another dispatch. The child’s concurrency group only serialises such runs because `cancel-in-progress` is false. The successful manual run on 4 September created child run `33866357613`, already contradicting the 5–14 September boundary.

## Major

5. **A manual run on another branch dispatches that branch’s `corredor.yml`, so the reviewed child’s “never real” safeguards are not pinned or proven for that path.** The REST `ref` is the parent run’s mutable `GITHUB_REF_NAME`; for a manual trigger this can be the branch selected by the human, not the default branch described by the comment. The refusal of `real`, secret gating, and push conditions belong to the child workflow at that selected ref. If that branch’s child differs from the packaged copy, this file cannot guarantee the same effective behaviour.
