## Major

1. **English Places ships dark without a reader’s choice and overrides a remembered light choice on reload.** Its served root is `<html lang="en" data-theme="dark">`, whereas Portuguese Places has no theme attribute. The dark selector therefore applies even without JavaScript. With JavaScript, startup preserves the root’s dark attribute even when storage says `light`, contradicting the report’s default-light claim and capture record. References: built/en/places/index.html:1, built/lugares/index.html:1, public/js/tema.js:165, design/especime-v3/medicoes/p4-2026-10-02/capturas-p4.json:453.

2. **N3 accepts a dangerous one-character guard change because the copied checker compares lengths instead of contents.** The diff requires exact string equality; the copied file requires only equal length. I executed the copied function against a guard with `===` changed to `!==`: both strings have 132 characters, N3 reports no errors, and the changed guard selects dark with empty storage. The six N3 plants do not include this mutation, so their green record does not prove character-for-character protection. References: scripts/check-pais.mjs:457, diff.patch:2440, tests/pais/pais.mjs:105.

3. **The copied menu declaration disagrees with both the diff and the built menus.** The copied array puts `sobre` before `uniaoEuropeia`; the diff puts the Union between Studies and About. Masthead renders that array in order, so rebuilding the copied source produces a different menu from the supplied HTML in both editions. N1 expects the diff’s order and would reject the rebuilt result. References: src/lib/navegacao.mjs:12, diff.patch:3169, src/components/Masthead.astro:25, scripts/check-pais.mjs:496, built/en/index.html:1.

4. **Removing an INE published-form field makes a precision defect pass the decimal cell.** In an isolated execution, `86,6` against published `86,60` correctly failed. Removing `ind_string` from the same excerpt produced zero errors and moved the row into `por_ler`, because the published-form reader returns `null` and the fallback continues. None of the sixteen plants tests losing this field, so declining coverage can coexist with a green result. References: scripts/casas-decimais.mjs:95, scripts/casas-decimais.mjs:157, scripts/casas-decimais.mjs:188.

5. **TM1–TM4 never test a reader choosing dark through the dark button.** TM3 preloads `dark` into storage, then clicks only the light button and reloads. A handler changed to apply light for every click would preserve those assertions, while making the dark button useless. The eight plants exercise markup, sizing, guards and CSS rather than this missing interaction. References: tests/inicio/tema-e-menu.mjs:185, tests/inicio/tema-e-menu.mjs:196, tests/inicio/tema-e-menu.mjs:242, public/js/tema.js:172.

6. **The decisions scanner can report success and a read-file count after failing to read a requested text input.** A `RuntimeError` from `texto_do_git` becomes an empty string without an error or skip record. I simulated that failure in explicit-file mode: the scanner printed zero decisions in one text file and returned zero. Its positive control concerns another file and cannot establish that the requested input was read. References: scripts/leituras/decisoes-em-vigor.py:86, scripts/leituras/decisoes-em-vigor.py:133, scripts/leituras/decisoes-em-vigor.py:157.
