## A leitura, tal como o leitor a entregou

## Blocking

1. **The supplied Portuguese form exposes submissions in the URL and saves nothing.** Its built HTML uses `method="get"`, whereas the source and English page use POST. Submitting therefore places the text and optional contact in the request URL, exposing them to URL logging and browser history; the GET handler simply redirects to the form. References: `built/sugestoes/index.html:2`, `built/en/suggestions/index.html:2`, `src/views/SugestoesView.astro:54`, `api/sugestoes.js:85`.

2. **The public database RPC bypasses the honeypot and trusted IP-based limiting.** The supplied endpoint and public key reach a function executable by `anon`, whose `p_marca` is entirely caller-controlled. A caller can rotate marks, bypass the Vercel function and consume the shared allowance; the database also accepts arbitrary mark text rather than requiring a salted hash. References: `api/sugestoes.js:28`, `supabase/migrations/2026-10-02-caixa-das-sugestoes.sql:32`, `supabase/migrations/2026-10-02-caixa-das-sugestoes.sql:51`, `supabase/migrations/2026-10-02-caixa-das-sugestoes.sql:67`.

3. **The copied honeypot rejects only the exact trimmed value `robot`.** The diff rejects every nonempty value, but the copied function uses `=== 'robot'`. Mocked requests with other filled values, including the cell’s robot URL, call the database; uploaded files are also treated as empty. References: `api/sugestoes.js:63`, `api/sugestoes.js:102`, `diff.patch:155`, `tests/sugestoes/funcao.mjs:149`.

## Major

4. **The IP mark is neither hourly nor deleted after one hour.** Its hash contains only the fixed salt and IP, so the same IP produces the same identifier across hours until the salt changes. SQL merely sets an expiry: physical deletion waits for a later successful submission or the daily cleanup, contradicting the notice’s one-hour storage promise. References: `api/sugestoes.js:115`, `supabase/migrations/2026-10-02-caixa-das-sugestoes.sql:50`, `supabase/migrations/2026-10-02-caixa-das-sugestoes.sql:73`, `src/data/sugestoes.mjs:94`.

5. **The English privacy source promises sixty days against ninety days elsewhere.** The copied source says “sixty”, while SQL, the diff, Portuguese source and built English page say ninety. Repeating the brief comparison yields 23 matching texts out of 24, contradicting the report’s claim that all texts remain verbatim. References: `src/data/sugestoes.mjs:96`, `diff.patch:2666`, `supabase/migrations/2026-10-02-caixa-das-sugestoes.sql:73`, `built/en/suggestions/index.html:2`, `relatorio-construtor.md:36`.

6. **The SQL does not enforce the stated limits under all request timings.** The daily count and subsequent insert have no shared lock or serialization, allowing concurrent transactions to pass the same ceiling check. The hourly counter expires relative to the first send rather than counting the preceding hour, so the result page’s “last hour” statement does not describe the mechanism. References: `supabase/migrations/2026-10-02-caixa-das-sugestoes.sql:46`, `supabase/migrations/2026-10-02-caixa-das-sugestoes.sql:51`, `supabase/migrations/2026-10-02-caixa-das-sugestoes.sql:57`, `src/data/sugestoes.mjs:116`.

References: `tests/sugestoes/funcao.mjs:212`, `diff.patch:3713`, `tests/sugestoes/funcao.mjs:314`, `tests/sugestoes/funcao.mjs:348`, `relatorio-construtor.md:39`.
