## Blocking

**B1. The breaker misses the exception produced by its own prover.** The report says `ReadTimeout` trips it, but the whitelist is only `ConnectTimeout`, `Timeout`, `ConnectionError`, `ProxyError`, and `ChunkedEncodingError`; matching is by exact class name, so subclassing does not help (`relatorio-construtor.md:139-145`, `corredor.py:274-294`). The local server sleeps before sending headers, which Requests reports as `ReadTimeout`; therefore all five requests proceed and the prover cannot produce the claimed one-request PASS (`corredor.py:1131-1135`, `corredor.py:1153-1187`, `http.py:463-468`). Consequently the claimed corridor 20, aggregate 83, and post-change `core.gate` PASS are incompatible with the supplied code (`relatorio-construtor.md:410-418`, `relatorio-construtor.md:433-451`). The GitHub rehearsal does not rescue this: the report explicitly says the breaker never fired there and remains unproved in production (`relatorio-construtor.md:610-631`).

**B2. The house User-Agent guarantee is not enforced.** The configured value is actually `Mozilla/5.0 (compatible; OEstadoDoPais/corredor)`, not the reported exact `OEstadoDoPais/corredor` (`http.py:94-104`, `relatorio-construtor.md:202-205`, `relatorio-construtor.md:598-603`). The daily `condicional()` paths inherit that Mozilla-compatible value, but `get()` and `post()` build a `PreparedRequest` from caller headers and pass it directly to `Session.send()`, bypassing the session header that holds the configured UA; with no caller header, the house UA is absent (`http.py:279-285`, `http.py:531-562`). `head()`, `condicional()`, and `download()` also permit a caller-supplied `User-Agent` to override the session value (`http.py:354-365`, `http.py:369-427`, `http.py:475-502`). `for_source()` can deliberately select the forged browser UA for an official source, which the report itself admits for Portal BASE (`http.py:70-92`, `http.py:583-599`, `relatorio-construtor.md:241-257`). Therefore an official request can still leave without the house UA or with a browser UA.

**B3. A changed body can be lost permanently in `real`.** Bodies are stored only in the runner before readers run (`corredor.py:446-452`). The durable archive push occurs after the archive and site gates, so a reader failure, gate failure, rejected push, cancellation, or archive-push failure leaves the new body only on the ephemeral runner (`corredor.yml:357-418`, `corredor.yml:428-441`). In `real`, the always-running artifact contains only `relatorio/` and `arquivo/indice.jsonl`; bodies are uploaded only in `ensaio` (`corredor.yml:525-543`). The resulting artifact can therefore contain an index naming a body that was neither pushed nor uploaded. The failure issue falsely tells the operator that the bodies are in the artifacts in every mode (`corredor.yml:555-580`).

| Effective mode | Artifact result |
|---|---|
| `ensaio` | Report and index for 14 days, plus `arquivo/sha256/` for 7 days (`corredor.yml:525-543`) |
| `real` | Report and index for 14 days; no bodies (`corredor.yml:525-543`) |
| `dormente`, or refused manual `real` | The `corredor` job is skipped, so no artifact steps run (`corredor.yml:156-189`) |

Missing paths only warn, rather than failing the artifact step (`corredor.yml:530-543`).

**B4. “The archive has the body” is not proved.** A regular file is classified as `presente` merely because it exists; its bytes are never hashed against its pathname during the invariant check (`arquivo.py:361-384`, `arquivo.py:470-495`). An LFS pointer is accepted solely because its textual OID equals the path SHA; the code never checks that the LFS server still has that object (`arquivo.py:348-384`, `portao_vintage.py:212-230`). Worse, when a matching pointer exists, `guardar()` discards newly fetched bytes immediately, so a missing remote LFS object stays missing even though the run possessed a recoverable copy (`arquivo.py:288-315`). The literal “every changed raw file is archived” is also false for normalized INE responses: a different raw SHA with an unchanged comparison SHA is classified equal and not stored (`corredor.py:337-343`, `corredor.py:449-476`, `arquivo.py:146-157`).

**B5. The patch and full code copies are not one code state.** The patch declares post-image blob `9c65337` for `core/http.py`, but the supplied `http.py` hashes to `ae1d7f79…`; it declares `1100662` for `indicators/corredor.py`, while the supplied copy hashes to `bdf1c0ef…` (`diff-motor.patch:338-342`, `http.py:1`, `diff-motor.patch:1384-1388`, `corredor.py:1`). The visible patch hunks agree, so the unexplained drift lies elsewhere in those full files. The package therefore cannot establish which version belonged to reported commit `4c184be` (`relatorio-construtor.md:14-16`).

## Major

**M1. The breaker can falsely silence a healthy host.** It opens after one attempt, with no retry or threshold (`corredor.py:418-438`). `ConnectTimeout`, generic `ConnectionError`, `ProxyError`, and especially `ChunkedEncodingError` can be transient or specific to one response; nevertheless every remaining URL on that host is written as inaccessible without being requested (`corredor.py:274-306`, `corredor.py:540-557`). Conversely, all unlisted `RequestException` classes do not trip it; the timing-based justification for excluding `SSLError` is not a property of that exception class (`corredor.py:266-294`, `http.py:463-468`). Policy responses such as repeated 429/503 also never open it because they carry a status rather than `erro` (`http.py:403-418`, `corredor.py:326-331`).

**M2. There is no asserted per-host wait ceiling of `timeout + 2s`.** Acquiring the machine-wide `flock` has no timeout (`http.py:148-183`). Requests streams the body with a socket timeout, not a total wall-clock deadline, so a slow trickle can exceed `--timeout` indefinitely (`http.py:421-462`). INE 429/503 responses can cause four requests plus 10, 30, and 90 seconds of backoff for each address (`http.py:124-129`, `http.py:403-418`). Non-policy hosts also have a default one-second throttle, not the reported zero, when an earlier address of that host was already attempted (`http.py:270`, `http.py:312-319`, `relatorio-construtor.md:146-151`). The only external cap is the whole job’s 60-minute timeout (`corredor.yml:184-191`).

**M3. Redirects bypass the destination host’s gate.** `condicional()` acquires the gate for the original URL and then lets Requests follow redirects internally; it never re-enters `_gate()` for the destination netloc (`http.py:132-149`, `http.py:421-427`). A redirect to `www.ine.pt` can therefore arrive concurrently with another INE request while holding a different host lock. If the redirected request fails, the breaker attributes the failure to the original host because it keys state before requesting (`corredor.py:418-435`).

**M4. The vintage “coverage” gate counts absences as captures and ignores URL provenance.** It marks a claim covered whenever its ID occurs in any index row’s `medidas`, regardless of whether that row has a body or even a successful HTTP result (`portao_vintage.py:89-118`). The corridor writes `medidas` on absence rows too (`corredor.py:485-507`). An old capture for claim ID `x` also satisfies coverage after `x` changes to a different `source_url`, because no ID-to-URL comparison exists (`portao_vintage.py:94-117`). The rehearsal illustrates the first hole: the gate passed with one absent address supporting four inaccessible lines (`relatorio-construtor.md:554-555`, `relatorio-construtor.md:604-608`).

**M5. The append-only baseline still fails open.** A shallow clone is sufficient to compare against `HEAD`, but `indice_commitado()` converts every nonzero `git show` result into the legitimate vintage-zero value `None`; corruption, permission failure, or another Git error silently disables the committed baseline (`arquivo.py:211-245`, `arquivo.py:248-264`). The hook incident has a real narrow fix: `GIT_DIR`, `GIT_INDEX_FILE`, and the other listed variables are removed, and the prover identity moved to `git -c` (`arquivo.py:187-208`, `arquivo.py:627-649`). The claimed known-positive only exercises contaminated `GIT_DIR` and `GIT_INDEX_FILE`, and exists here solely as report text, `[verify]` (`relatorio-construtor.md:516-526`).

**M6. The site is not built “only in the pushing run.”** `npm ci` and the site gates depend only on `so_devidas == ''`, not on `modo == real`; a normal `ensaio` builds the site even though it cannot push (`corredor.yml:330-340`, `corredor.yml:400-418`, `corredor.yml:428-459`). The report’s own rehearsal was `ensaio` and spent 13m31s in those gates, directly contradicting that description (`relatorio-construtor.md:532-556`).

**M7. The deploy poll’s eight-minute ceiling is false.** It performs up to eight 30-second curls and sleeps 60 seconds after every miss, including after the eighth request (`corredor.yml:496-510`). A complete miss therefore takes at least eight minutes and can take about twelve minutes before `verify:deploy`, not at most eight. The polling curl also uses curl’s default UA and no house gate, although its target is the observatory’s own site rather than an official source (`corredor.yml:496-502`).

**M8. The workflow does not guarantee staying under the quoted free-plan limits.** The scheduled estimate is arithmetically below the report’s 2,000-minute allowance, but `workflow_dispatch` permits unlimited billed rehearsals and contains no budget guard (`corredor.yml:86-98`, `relatorio-construtor.md:656-665`). Three retained rehearsals at the reported 179,114,127 bytes each total 537,342,381 bytes, already above the quoted 500MB artifact allowance (`corredor.yml:536-543`, `relatorio-construtor.md:642-654`). Skipping LFS smudge avoids the known 106MB daily download, but new LFS bodies can still be uploaded by `git add` and `git push`; no bandwidth ceiling or accounting check exists (`corredor.yml:294-323`, `corredor.yml:428-441`). Current plan limits themselves are `[verify]`; the package provides only the builder’s quoted limits.

**M9. The rehearsal evidence is insufficient for several headline claims.** The package contains quoted outputs but no raw run log, JSON report, or downloaded artifacts, so the run’s green result, 79-address data, reader exit codes, and durations are `[verify]` from this package alone (`LEIA-ME.md:3`, `relatorio-construtor.md:530-561`). “19 billed minutes” is explicitly inferred because the billing endpoint returned zero; it is not an observed billing value (`relatorio-construtor.md:563-569`). It proves nothing about the breaker in production because no breaker event occurred (`relatorio-construtor.md:610-631`), and the workflow rehearsal does not run `core.gate` or `provas_test` (`corredor.yml:357-418`).

**M10. The prover counts are not protected.** The reported arithmetic is 14 + 6 + 43 + 20 = 83, but `provas_test` accepts any positive count from each prover and has no expected per-prover or total floor (`provas_test.py:71-83`, `provas_test.py:91-125`, `relatorio-construtor.md:410-418`). A prover could lose most checks and the commit gate would remain green. With B1 unfixed, the supplied corridor prover instead exits nonzero, so the aggregate never reaches a PASS.

**M11. SSH host verification is bootstrapped from the unauthenticated connection it is meant to verify.** The workflow runs live `ssh-keyscan github.com` and immediately trusts that output instead of pinning GitHub’s known host keys (`corredor.yml:252-275`). A network impersonator could therefore accept the archive or site push while the workflow reports success.
